# Ядро ADCR2R8: контракт интеграции

Реализовано на Python 3.10+ без внешних зависимостей. Ядро не импортирует
парсер или GUI. На вход принимает последовательность целых чисел `int`:
`0x3120` и `12576` — одно и то же число. Строки вроде `"0x3120"` необходимо
преобразовать до вызова ядра. ASM-файл обрабатывает существующий парсер.

## Компоненты

- `regs`: 16 регистров R0–R15, по 16 бит, беззнаковые значения 0…65535.
- `imem`: 4096 слов по 16 бит, отдельная память команд.
- `dmem`: 4096 слов по 16 бит, отдельная память данных.
- `pc`: адрес следующей инструкции в словах; `ir`: первое слово последней исполненной команды.
- `ZF`, `CF`, `SF`: ноль, перенос/заём, старший бит результата.
- `halted`: остановка командой HALT.

Двухадресная операция записывает результат в первый регистр: `ADD R3, R2`
означает `R3 = (R3 + R2) & 0xFFFF`. Стек и указатель стека в этой версии
не предусмотрены: примеры стековых команд в приложенных материалах относятся
к безадресной архитектуре. Ввод данных и чтение результата выполняются через
`dmem`; отдельных команд IN/OUT нет.

## Кодировка и совместимость

Команды данных сохраняют формат проекта:

```text
15          12 11        8 7         4 3         0
    opcode         Rd         Rs         mode
```

| mode | Источник | Длина |
|---|---|---|
| 0 | Rs | 1 слово |
| 1 | константа во втором слове | 2 слова |
| 2 | dmem[адрес из второго слова] | 2 слова |
| 3 | dmem[Rs] | 1 слово |

Коды MOV…NOT находятся в `src/cpu/constants.py`. LOAD и STORE принимают только
режимы 2/3. STORE записывается как `STORE [адрес], Rd`, при этом Rd кодирует
регистр данных. INC/DEC/NOT используют только Rd, режим 0, Rs=0.
Для режимов 1/2 поле Rs равно нулю. Адрес данных — 0…4095.
MUL запрещён с Rd=R15, поскольку регистра R16 нет.

**Исправление неоднозначного формата переходов:** прежний `opcode:address`
совпадал с командами данных (например, 0x7000 означало одновременно MUL и HALT).
Теперь младшая тетрада 0xF обозначает управляющую команду:

```text
первое слово: 0x00cF
c: JMP=0, JZ=1, JNZ=2, JC=3, JNC=4, JS=5, JNS=6, HALT=7
второе слово: абсолютный адрес 0…4095 (только для переходов)
HALT: одно слово 0x007F
```

Пример `JNZ loop`, где `loop` по адресу 2: `[0x002F, 0x0002]`.
Парсер учитывает новую длину при расчёте меток. Старые машинные списки нужно
пересобрать; старую неоднозначную кодировку ядро не поддерживает.

В предоставленном **примере требований** указана фиксированная длина команд.
В текущем проекте сохранён исходный формат переменной длины 1/2 слова из README.
Если этот пункт обязателен именно для вашей сдачи, текущая версия ему не соответствует:
потребуется согласованная миграция ядра, парсера и таблиц отчёта на фиксированный формат.
Разрядность данных и регистров при такой миграции можно оставить 16 бит.

## Семантика флагов

| Команды | Результат и флаги |
|---|---|
| MOV, LOAD, STORE, переходы, HALT | флаги сохраняются |
| ADD, ADC, INC | результат по модулю 65536; CF при переносе, ZF/SF по результату |
| SUB, SBB, DEC, CMP | CF при заёме; ZF/SF по младшим 16 битам разности |
| CMP | как SUB, без записи регистра |
| ADC / SBB | учитывают старое значение CF |
| MUL | беззнаковое произведение: Rd — младшие 16 бит, Rd+1 — старшие; CF сохраняется; ZF/SF по полному 32-битному результату |
| DIV | беззнаковое целочисленное Rd // источник; остаток отбрасывается; CF=0, ZF/SF по результату |
| AND, OR, XOR, NOT | CF=0, ZF/SF по результату |

Это собственная ISA, а не точная семантика x86. В частности, INC/DEC меняют CF.
JS/JNS проверяют бит знака, но не заменяют сравнение знаковых чисел с учётом
переполнения: флага OF нет. Для беззнакового сравнения используются CMP и JC/JNC.

## API для GUI и парсера

```python
from src.cpu.cpu import CPU
from src.assembler.parser import assemble_file

cpu = CPU()
cpu.load_program(assemble_file('src/programs/find_max.asm'))
cpu.load_data(0x100, [6, 10, 45, 2, 65535, 8, 3])

preview = cpu.decode()                 # без исполнения; .assembly, .rd, .rs, .mode
executed = cpu.step()                  # одна инструкция целиком, включая второе слово
state = cpu.snapshot()                 # независимые копии списков для таблиц GUI
steps = cpu.run(limit=10000)            # число выполненных инструкций
assert cpu.halted
assert cpu.dmem[0x200] == 65535
```

- `load_program(words)` сначала валидирует весь вход, копирует программу,
  обнуляет хвост imem и сбрасывает регистры/флаги/PC. dmem сохраняется.
- `reset()` сбрасывает регистры/флаги/PC/IR/halted/last_instruction,
  сохраняя обе памяти. Это не восстановление первоначального массива.
- `load_data(address, values)` проверяет и записывает блок данных целиком.
- `step()` возвращает `DecodedInstruction`; после HALT возвращает None.
- `decode(address=None)` возвращает поля команды и ассемблерное представление.
  В управляющей команде `.rs` содержит код условия, `.operand` — адрес перехода.
- `last_instruction` описывает последнюю успешно выполненную команду.
- `run(limit)` останавливается на HALT или после limit инструкций. Если
  `halted=False`, выполнение можно продолжить. Лимит не считается ошибкой.
- Ошибки адреса, режима, размера слова — `CPUError` (подкласс ValueError).
  Деление на ноль — `ZeroDivisionError`. Ошибочная инструкция не меняет состояние.
- Незаполненная imem содержит нули (`MOV R0, R0`). Конец переданного списка не
  является HALT. При выходе PC за imem следующая попытка шага вызывает CPUError.
  Переходы используют адреса слов; попадание на слово операнда не запрещается.
- Публичные списки оставлены для совместимости. Для записи используйте методы;
  изменение длины списков напрямую не поддерживается. Потокобезопасности нет.
- Для отзывчивого tkinter GUI вызывайте `step()` или `run(limit=100)` через `after`,
  затем обновляйте таблицы. Не запускайте бесконечный цикл в обработчике кнопки.

## Примеры и проверка

```powershell
python -m src.cpu.demo
python -m unittest discover -s tests -v
```

Демонстрация использует существующие ASM-файлы через парсер и выводит машинные
слова, результат и число исполненных инструкций без запуска GUI.

`find_max.asm`: N по адресу 0x100, элементы с 0x101, максимум в 0x200.
Для пустого массива принято значение результата 0. Массив должен помещаться
в память; используйте рекомендуемые заданием 6–15 элементов.

`convolution.asm`: два массива ровно по 6 элементов, размеры по 0x100 и 0x200,
элементы с 0x101 и 0x201. Программа использует константу 6.
Результат хранится в 0x300 (биты 0–15), 0x301 (16–31), 0x302 (32–47).
Максимум `6 * 65535**2 = 25769017350` требует 35 значащих бит.
После ADD младших слов выполняются ADC среднего и ADC старшего слова;
это сохраняет точность для всех допустимых входных 16-битных чисел.

Тесты проверяют машинный ввод, все операции, четыре режима адресации,
оба исхода каждого условного перехода, сохранение состояния при ошибках,
границы памяти, HALT/reset/reload, интеграцию парсера и программы на
детерминированных случайных и граничных наборах данных.

GUI остаётся отдельной частью проекта; `main.py` пока открывает его заглушку.
SASM используется как ориентир интерфейса (редактор, отладчик, просмотр состояния),
а не как бинарно совместимый процессор: https://dman95.github.io/SASM/english.html.
